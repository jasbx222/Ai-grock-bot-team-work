# مكتب الوكلاء 3D 🏡☕

نسخة تجريبية لمكتب افتراضي ثلاثي الأبعاد بأجواء شتوية دافئة (ليل، ثلج، مدفأة، شاي)،
يجمع الوكلاء كعائلة وحدة حول طاولة مشتركة. كل وكيل عنده شخصية بشرية واسم، وتشوف حالته
(يشتغل، ينتظر، عنده مشكلة، خلّص) وتگدر تحچي وياه من داخل التطبيق.

> ⚠️ **نسخة تجريبية:** الحالات تجي من ملف `status.json` نموذجي (مكتوب عليه «بيانات تجريبية»)،
> وردود المحادثة **تجريبية محلية** ومعلّمة بـ «ردّ تجريبي». ماكو أي ربط حقيقي بالوكلاء لحد الآن.

## المتطلبات
- Node.js 18 أو أحدث
- (للتطبيق) Flutter 3.x و Android SDK و JDK 17

## التشغيل على المتصفح
```bash
npm install
npm run build      # يبني النسخة النهائية في dist/
npm run serve      # يفتح على http://127.0.0.1:5180
```
وضع التطوير (تحديث مباشر):
```bash
npm run dev        # http://127.0.0.1:5180
```
النسخة تشتغل بدون إنترنت (الخط العربي و Three.js مضمّنة).

## تطبيق أندرويد (Flutter)
التطبيق في `flutter_app/` ويعرض نفس المكتب أوفلاين داخل WebView (سيرفر محلي على 127.0.0.1).
```bash
cd flutter_app
./tool/sync_web.sh            # يبني الويب وينسخه إلى assets/web
flutter pub get
flutter analyze
flutter build apk --debug     # الناتج: build/app/outputs/flutter-apk/app-debug.apk
```
لنسخة release تحتاج تضيف مفتاح توقيع خاص بيك (`key.properties`) — ماكو مفاتيح بالمستودع.

## التحكم
- **نظرة عامة:** سحب بالماوس/الإصبع للدوران، عجلة/قرص للتكبير، زر يمين/إصبعين للتحريك.
- **تمشّى بالمكتب:** منظور الشخص الأول — `W A S D` أو الأسهم للمشي، `Shift` للركض، والماوس للنظر.
  على الموبايل: عصا تحكم افتراضية + سحب الشاشة للنظر. فيه تصادم مع الجدران والأثاث.
- 📍 بقائمة الأشخاص = روح لمكتبه، 💬 = افتح المحادثة. الضغط على أي شخصية يفتح المحادثة.
- سجل المحادثات ينحفظ بالمتصفح (localStorage).

## إضافة بوت جديد (بدون تعديل كود)
كل شي (الشخصيات، المكاتب، الأسماء، قائمة المحادثة، الحالة) يتولّد من `public/agents.json`.
أضف عنصر جديد للمصفوفة:
```json
{
  "id": "support-bot",
  "agentName": "support bot",
  "person": "مريم",
  "role": "دعم العملاء"
}
```
- `id` لازم يكون فريد، ونفسه يُستخدم في `status.json`.
- المكتب ينحجز تلقائياً بمقعد فارغ حول الطاولة المشتركة، وإذا امتلأت الطاولة تطول والغرفة تتوسّع.
- إذا ما حطّيت `look`، الشكل يتولّد تلقائياً وبشكل ثابت من الـ `id` (hash من نوع FNV-1a يختار
  لون البشرة، الشعر وتسريحته، الملابس، النظارات، اللحية/الحجاب، ولون البطانية) — نفس الـ id يعطي نفس الشكل دائماً.
- تگدر تحدد الشكل يدوياً، مثال:
```json
"look": { "female": true, "skin": "#c68e6a", "hair": "#2b1a12", "hairStyle": "long",
          "shirt": "#4f8a8b", "glasses": true }
```
  تسريحات الشعر: `short`, `curly`, `bob`, `long`, `hijab`. وخصائص اختيارية: `beard`، `glasses`، `pants`، `shoes`، ولون البطانية `"blanket": "#8a5a3c"` على مستوى الوكيل.
- `props` (اختياري): أدوات المكتب مثل `["monitor","laptop","headset","phone","tea"]`.

تجربة جاهزة لستة وكلاء:
`http://127.0.0.1:5180/?agents=agents.sample-6.json&status=status.sample-6.json`

أي وكيل يظهر بـ `status.json` وماله تعريف، ينضاف تلقائياً بشكل افتراضي.
الصفحة تراقب `agents.json` كل 5 ثواني وتعيد التحميل إذا تغيّرت قائمة الوكلاء.

## صيغة status.json
```json
{
  "sample": true,
  "updatedAt": "2026-10-31T13:05:00+03:00",
  "agents": [
    { "id": "dev01b", "status": "working", "task": "وصف المهمة" },
    { "id": "messaging", "status": "problem", "reason": "سبب المشكلة" },
    { "id": "marketing", "status": "done", "result": "النتيجة" }
  ],
  "messages": [ { "id": "m1", "from": "planbot", "to": "dev01b" } ]
}
```
الحالات: `working` (يكتب + فقاعة المهمة)، `waiting` (يشرب شاي)، `problem` (ضوء أحمر + السبب)،
`done` (علامة ✓)، `offline`. كل رسالة جديدة بـ `messages` تطلع كورقة طايرة بين المكتبين.
الملف ينقرأ كل 5 ثواني.

## ربط المحادثة لاحقاً
كل الإرسال يمر من دالة وحدة: `sendMessage(agentId, text)` في `src/chatAdapter.js`.
الإعدادات في `src/config.js` أو قبل تحميل الصفحة:
```html
<script>
  window.AGENT_OFFICE_CONFIG = { chatEndpoint: "https://example/your-endpoint", statusUrl: "status.json" };
</script>
```
عقد مقترح (placeholder، مو API حقيقي): `POST {agentId, text}` ← `{reply}`.
بدون `chatEndpoint` يبقى الوضع تجريبي والردود معلّمة «ردّ تجريبي».
في تطبيق Flutter تگدر تحدد `kChatEndpoint` و `kStatusUrl` في `flutter_app/lib/office_page.dart`.

## الجودة والأداء
- إضاءة PBR، ظلال ناعمة عالية الدقة، AO (GTAO)، Bloom خفيف، ACES + sRGB، ضباب، MSAA.
- جودة متكيّفة: تنزل تلقائياً (AO ← الدقة ← الظلال) إذا الـ FPS نزل. الدقة القصوى DPR 2 (1.5 للموبايل).
- تجاوز يدوي: `?quality=high|medium|low` و `?noadapt`.
